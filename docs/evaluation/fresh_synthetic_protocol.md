# Fresh synthetic four-banner evaluation: protocol, frozen 27 Oct 2026 before any model call

**What this is.** A small smoke evaluation on four AI-generated, fictional banners (`docs/evaluation/fresh_synthetic/`, hashes in
`SHA256SUMS.txt`, provenance in `provenance/PROVENANCE.md`). They were generated by the owner's assistant with knowledge of the
product's support scope. It is a **fresh synthetic convenience set**: not a sealed independent benchmark, not real-world
validation, not user research. Four rows cannot support a population claim or a superiority claim.

## Frozen before inference
- **Code:** HEAD `bfc1f87` plus this protocol and the two scripts committed with it. Prompts: `prompts/campaign_vision.md`
  sha256 `b5b6c8a7...6777dd`, `prompts/campaign_explain.md` sha256 `c0f9a275...454ab`.
- **Models:** reading `nvidia/Nemotron-3.5-Super-VL`; overflow-question wording `nvidia/nemotron-3-super-120b-a12b` (only if a
  question appears). No other model. Vision list price assumed $0.30 / $0.90 per million tokens (ledger estimate; the Nebius
  dashboard is authoritative).
- **Inputs:** the four originals, unchanged, in `run_order.txt` order (banner_01..04). The app's own banner preprocessing resizes
  1672x941 to 1280x720 with `drawImage` (ratio 0.9995 of 16:9, so a 0.05% non-uniform stretch, not letterboxing); the resized PNG
  and its hash are saved per image.
- **Preflight (before inference, `preflight.json`):** the app's own flat-border detector (`apps/web/src/snap.ts backgroundOf`:
  border at least 92% within RGB distance 40 of its median). banner_01..03: flat, **within** the documented simple-background
  contract; banner_04: not flat, **outside** it. The app does not refuse non-flat images: it only turns snapping off and says
  "place them yourself". "Intended supported" was never certification; rows below report what happened.
- **Extraction input:** only the image (and the fixed production prompt). No annotation, generation prompt, expected text,
  support label or brief reaches the model. Annotations in `evaluator_only/` are not read until the raw extraction of an image is
  saved and committed (`stage_a/`).
- **Budget manifest:** at most 4 vision reads (one per image; the existing code resends once only after a truncated reply, and any
  such second call is logged), at most 4 question-wording calls, no page reads, no fact/copy calls. The incremental realised-spend stop is **$0.25**, checked from `calls.jsonl` by the operator after every image. The server's own cap is
  set to `DEMO_MODEL_MAX_USD=1.00` only because the app reserves about $0.48 per model session before a call (a first attempt with a
  $0.25 server cap made no model call: `run0_setup_failure_no_model/`); that reserve is not spend. All of it is far inside the owner's $5 total. Stop on cap, on a systematic failure, or after the
  four images; never to improve a score. Every call is logged in `calls.jsonl` (role, raw reply text, usage; no images).

## Procedure and scoring (fixed now)
1. **Stage A (first attempt, kept):** upload through the real Adapt screen, save the server's raw response and the editor state
   after the app's own snapping, a screenshot, timings. Commit.
2. **Scoring of the raw extraction (after Stage A is committed):** per expected visible text role, exact string match after the
   normalisation rule stated in the evaluator notes (line breaks/whitespace only); role present/absent; box on target judged
   by overlap with the annotated element (at least 70% coverage by eye on the overlay, and IoU if annotated boxes exist).
3. **Stage B (corrected completion):** a scripted operator applies a fixed rule, counted per field: a text field is replaced by the
   expected text iff it differs; a box is replaced iff it is off target; a wrong or missing role is fixed or added. Then the
   banner is built, adapted and checked. If a question appears: choose split if it fits, otherwise shrink; if neither fits, answer
   "neither". No headline is shortened, no overflow is invented, no background is simplified.
4. **Unsupported image (banner_04):** report what the app said and did. Reconstruction of a detailed background as a flat
   colour is a **lossy** result, never a preservation success; count it as such. Distinguish automatic refusal from a documented
   limitation the operator noticed.
5. **Reported per row (blank is not zero):** exact-content correctness, completeness, corrections count, model calls, cost,
   layout/checker defects, internal visual judgment (labelled as such), total elapsed seconds. **Active human time is not
   measured** (the operator is a script); the manual comparator is a separate human task (`manual_timing_template.csv`) and is
   **not run** unless a person does it.
6. **Reruns:** the first attempt of each image is never overwritten. Any later attempt is labelled "development rerun" and
   the product is not tuned on these four and then re-presented as untouched.

## Known limits stated in advance
Generated images have mild shading and product shadows, so "flat" means flat border, not a constant colour. The app crops the
logo and product as rectangles from the image; the preserved pictures are the generated ones. The judge of visual quality and of
box coverage is the assistant that built the product (a bias; overlays are saved so the owner can check).
