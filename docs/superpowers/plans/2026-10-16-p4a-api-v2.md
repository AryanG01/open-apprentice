# API v2 Backend Implementation Plan (Plan 4A)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The complete teach → clarify → correct → reuse → export flow works over HTTP on real `.drawio` files: `/api/v2` with
anonymous owners, documents, mappings, teaching and correction sessions, apply runs, activation and export, all driven by the new
learning core and stored in the Store (local folder or GCS).

**Architecture:**
- A thin FastAPI router (`api/v2/routes.py`) calls a service layer (`api/v2/service.py`) of plain functions that take a `V2` context
  object (store, render function, proposers, ledger, dispatcher). Tests drive the service directly and through `TestClient`, with a fake
  renderer, so no browser is needed except in the engine-marked integration test.
- Session progress runs in a `LocalDispatcher` (a thread pool, one worker per session at a time). Plan 4B swaps in Cloud Tasks behind
  the same `Dispatcher` protocol.
- Offline learning uses a deterministic label-rule enumerator, `concepts/label_enumerative.py`, with no model. Live learning uses a
  provider adapter (`providers/teaching_adapter.py`) that bridges the async provider API to the executors' synchronous `Proposer`
  protocol. Live mode is server-side only (`DEMO_MODEL_ENABLED=1`), and its global cap is the durable `teaching.accounting.Ledger`.

**Tech Stack:** FastAPI 0.115, Pydantic 2, httpx, stdlib `hmac` for signed owner cookies (no new dependency), the existing
`open_apprentice.teaching`, `skills.versions`, `drawio`, `storage` packages.

**Spec:** `docs/superpowers/specs/2026-10-15-teach-correct-reuse-design.md` sections 8 (API), 3.7 (budgets), 4 and 5 (through the
executors), 6 (through `drawio/`). Plans 4B (Cloud Tasks + OIDC internal route + generated probes) and 4C (screens + journey test) follow
this one; the roadmap records the split.

## Global Constraints

- Python 3.12 target, black, ruff, type hints, conventional commits; no `eval`/`exec`/dynamic code loading.
- Agent-visible and learning-core packages never import the evaluator. The new `concepts/label_enumerative.py` is covered by the
  existing "Agent/skills/concepts/providers never import the evaluator" contract and must not import `evaluation.labels`.
  `open_apprentice.api` is not in a contract, but must not import `evaluation.labels`, `evaluation.verifier`, or `evaluation.episodes`
  either; a test asserts it.
- `PROVIDER_MODE=mock` stays the default. Live model calls only when `DEMO_MODEL_ENABLED=1` server-side **and** a provider is configured;
  clients cannot request it. This plan runs no paid call; every test uses the offline enumerator or `MockProvider`.
- Ownership: anonymous owner id in a signed `HttpOnly`, `SameSite=Lax` cookie (`oa_owner`). Every stored resource records its owner and
  every route checks it; another owner's resource answers 404 (never 403, which would confirm existence).
- Routes live under `/api/v2`; a test asserts the legacy `/api/teach`, `/api/svg`, `/api/replay` routes still work and do not shadow v2.
- Provenance on every session, run and artifact, two dimensions: `model ∈ {Live, Recorded, Fixture}` × `teacher ∈ {You, Simulated}`.
  The offline enumerator is reported as `Fixture` (deterministic offline candidate source, no model).
- Budgets per spec 3.7 come from `StepConfig` / `CorrectionConfig` (already enforced by the executors). Spend shown on `GET /sessions/{id}`
  is the durable ledger's `exposure()` split into recorded / reserved / uncertain.
- Upload ≤ 2 MB (the reader enforces it); request bodies for JSON routes ≤ 256 KB.
- When live inference is unavailable (disabled or cap reached) a session requested as live is refused with
  `409 {"error": {"code": "LIVE_UNAVAILABLE", "message": "Live inference is unavailable. Open the recorded example."}}`; never a silent swap.
- States and wording follow spec 8 exactly (teaching `imported → mapped → teaching → (waiting_for_model | waiting_for_answer)* →
  preview_ready → committed`; correction `draft → … → review → stored → activated | activation_rejected | failed`).

## Review Focus

1. **Cross-owner access:** every id-bearing route (documents, mapping, preview PNG, draft, sessions, responses, cancel, runs, export,
   skills, corrections, activate) must answer 404 for another owner's id, including ids guessed from a different owner's response. (Task 9 test.)
2. **Stale or duplicate answers:** a response for a request that is no longer outstanding, or with an old `intent_revision`, is refused
   with 409 and changes nothing; repeating an accepted response with the same request id returns the same result, not an error. (Task 6 test.)
3. **Concurrent advancement:** two quick `POST /responses` for the same session must not run two executors on one log at once; the second
   waits or is coalesced, and the log stays a single chain. (Task 5 test.)
4. **Tampered cookie or idempotency replay:** a cookie with a bad signature gets a fresh owner (no access to the old one's resources); the
   same `idempotency_key` with a different body is refused with 409 rather than silently returning the first result. (Tasks 1 and 9 tests.)
5. **Apply on a document that fails a check:** a run whose output fails conformance, preservation or layout for one document reports that
   document as blocked with the reasons from the receipt, publishes nothing for it, and still completes the others. (Task 7 test.)

```python
# src/open_apprentice/api/v2/identity.py
"""Anonymous owner identity: a random id in an HMAC-signed HttpOnly cookie (spec 8). A bad signature means a new owner, never access."""

from __future__ import annotations

import base64
import hashlib
import hmac
import uuid
from typing import Optional

COOKIE = "oa_owner"


def new_owner() -> str:
    return uuid.uuid4().hex


def _mac(owner: str, secret: bytes) -> str:
    return base64.urlsafe_b64encode(hmac.new(secret, owner.encode(), hashlib.sha256).digest()).decode().rstrip("=")


def sign(owner: str, secret: bytes) -> str:
    return f"{owner}.{_mac(owner, secret)}"


def verify(token: Optional[str], secret: bytes) -> Optional[str]:
    if not token or token.count(".") != 1:
        return None
    owner, mac = token.split(".")
    if not owner or not hmac.compare_digest(mac, _mac(owner, secret)):
        return None
    return owner
```

```python
# src/open_apprentice/api/v2/records.py
"""Owned JSON records in the Store. A record of another owner is indistinguishable from a missing one."""

from __future__ import annotations

import hashlib
import json
from typing import Callable

from open_apprentice.storage.store import PreconditionFailed, Store


class NotFound(Exception):
    pass


class IdempotencyConflict(Exception):
    pass


def _dumps(d: dict) -> bytes:
    return json.dumps(d, sort_keys=True, separators=(",", ":")).encode()


def put_new(store: Store, key: str, owner: str, body: dict) -> None:
    if not store.create(key, _dumps({**body, "owner": owner})):
        raise FileExistsError(key)


def load(store: Store, key: str, owner: str) -> tuple[dict, int]:
    b = store.get(key)
    if b is None:
        raise NotFound(key)
    d = json.loads(b.data)
    if d.get("owner") != owner:
        raise NotFound(key)
    return d, b.generation


def update(store: Store, key: str, owner: str, fn: Callable[[dict], dict]) -> dict:
    for _ in range(50):
        d, gen = load(store, key, owner)
        new = {**fn(d), "owner": owner}
        try:
            store.put(key, _dumps(new), if_generation=gen)
            return new
        except PreconditionFailed:
            continue
    raise RuntimeError(f"{key}: update contention")


def idempotent(store: Store, owner: str, key: str, request_digest: str, produce: Callable[[], dict]) -> dict:
    k = f"idem/{owner}/{hashlib.sha256(key.encode()).hexdigest()}.json"
    b = store.get(k)
    if b is not None:
        d = json.loads(b.data)
        if d["digest"] != request_digest:
            raise IdempotencyConflict("this idempotency key was used with a different request")
        return d["result"]
    result = produce()
    if not store.create(k, _dumps({"digest": request_digest, "result": result})):
        return idempotent(store, owner, key, request_digest, produce)  # lost a race: the stored one wins
    return result
```

**Files:**
- Create: `src/open_apprentice/concepts/label_enumerative.py`, `tests/unit/test_label_enumerative.py`

**Interfaces:**
- Consumes: `concepts.rule_text.parse_rule_text`, `concepts.rules.validate_rule`, `teaching.step.run_output` is NOT imported (concepts must not depend on teaching); use `concepts.rules.evaluate_rule` directly.
- Produces:
  - `class LabelEnumerator` with
    - `def propose(self, evidence_json: dict, round_kind: str, feedback: tuple[str, ...]) -> tuple[list[dict], dict, Fraction]` (the `teaching.executor.Proposer` protocol)
    - `def propose_scope(self, evidence_json: dict, round_kind: str) -> tuple[list[dict], dict, Fraction]` (the `correction_executor.ScopeProposer` protocol)
  - Candidates: `{"rule": list, "summary": str, "text": str}` for `propose`; `{"rule": list, "selector": str, "summary": str}` for `propose_scope`. Cost is always `Fraction(0)`; usage `{"source": "label_enumerative", "evaluated": n}`.
  - Template grammar (exact): for `side ∈ {right, below, left, above}`, `gap ∈ G`, `scope ∈ {all labels} ∪ {labels with role r : r in roles seen}`, the rule text

```
for o in objects {
  if o.kind == "label" {
    if <SCOPE> {
      let a = object(o.attached)
      move o to (<X>, <Y>)
    }
  }
}
```

    with `<SCOPE>` = `o.role == "<r>"` or `o.kind == "label"`; and per side (centre-aligned on the other axis):
    right `(a.x + a.w + g, a.y + (a.h - o.h) / 2)`, left `(a.x - o.w - g, a.y + (a.h - o.h) / 2)`,
    below `(a.x + (a.w - o.w) / 2, a.y + a.h + g)`, above `(a.x + (a.w - o.w) / 2, a.y - o.h - g)`.
  - `G` = the set of gaps implied by the evidence: for every moved label and every side, the gap that side would need (`new.x − (a.x + a.w)` for right, etc.), kept when it is a non-negative multiple of 1/64 ≤ 200; plus `{8, 12, 16}`.
  - `propose` returns at most 4 candidates that reproduce **every** evidence item exactly (checked with `evaluate_rule`), ordered by (text length, text); `round_kind == "contrastive"` returns up to 4 *further* fitting candidates not in `feedback`-named summaries (it is fine to return none). `propose_scope` returns, for the corrected labels, every (side, gap) rule that reproduces the corrected positions, paired with selectors `o.role == "<role of the corrected labels>"` and `o.kind == "label"`.
  - Evidence format consumed: the learning executor's `{"teaching_evidence": describe_compact(positives)}` items (`scene`, `labels_moved_to` keys as in `concepts/label_teaching.describe_compact`), and the correction executor's `{"base_program", "corrected_scene", "corrected_labels"}` plus the corrected positions. **Before implementing, print one real evidence dict from each executor** (`tests/unit/teaching/test_executor.py` and `test_correction_executor.py` fixtures) and match the exact keys; if the correction evidence lacks the corrected positions and scene, add them to `CorrectionExecutor._propose`'s evidence dict (`"corrected_scene_objects"`, `"corrected_output"`) in this task and record a ruling.

### Task 3: Live provider adapter

**Files:**
- Create: `src/open_apprentice/providers/teaching_adapter.py`, `tests/unit/test_teaching_adapter.py`

**Interfaces:**
- Consumes: `providers.base.Provider.complete_json`, `Message`, `CallContext`; `budget.Ledger`, `budget.Limits`; `concepts.hypotheses.HypothesisSet` (output schema with `candidates: list[CandidateOut]`; `CandidateOut.source() -> (ast, text)`); `concepts.rule_text.parse_rule_text`; `concepts.rules.validate_rule`, `RuleError`.
- Produces:
  - `class ProviderProposer(provider: Provider, prompt_path: pathlib.Path = PROMPTS / "hypotheses_labels.md", max_tokens: int = 6000)` with the `Proposer` protocol.
  - `class ProviderScopeProposer(provider: Provider, prompt_path: pathlib.Path = PROMPTS / "correction_scope.md", max_tokens: int = 6000)` with the `ScopeProposer` protocol.
  - Each call runs `asyncio.run(provider.complete_json(...))` (the executors run in worker threads, never on the event loop), with a fresh `budget.Ledger(Limits())` (the durable `teaching.accounting.Ledger` already reserved the worst case in the executor), and returns `(candidates, usage, cost)`. `usage = {"prompt_tokens", "completion_tokens", "usage_estimated", "provider_label", "model_id"}`. `cost = Fraction(str(usd))` when `usd` is known, **otherwise raise `ValueError("cost unknown")`** so the executor marks the attempt `outcome_unknown` at worst case (never a silent zero).
  - Malformed candidates (no rule text, parse or validation error) are dropped and counted in `usage["malformed"]`.
  - Provider exceptions propagate unchanged (the executor classifies them with `failure_kind`).
